## JSON Formatter & Validator

Format, validate, minify and repair JSON online. Get the exact line and column of every error, a collapsible tree view and sorted keys — private, in-browser.

### At a glance

- Formats JSON with 2 spaces, 4 spaces or tabs, or **minifies** it to a single line.

### Features

- **Precise error messages**: Instead of “Unexpected token”, you get a plain-English message such as “Expected ',' or '}' after property value” with the line, column and a pointer to the character.
- **One-click repair**: JSON copied from JavaScript, config files or Python often has comments, trailing commas or single quotes. **Fix mistakes** converts it to valid JSON and lists every change.
- **Exact numbers**: IDs, prices and big integers are kept character-for-character, so formatting never silently changes your data.

### Guide

#### The most common JSON errors — and how to fix them

JSON is stricter than JavaScript. These mistakes cause almost every “invalid JSON” error. All of them except missing commas, missing brackets and leading zeros can be repaired automatically with **Fix mistakes**.

| Error | Invalid | Valid |
| --- | --- | --- |
| Trailing comma | `{"a": 1,}` | `{"a": 1}` |
| Single quotes | `{'a': 'b'}` | `{"a": "b"}` |
| Unquoted key | `{a: 1}` | `{"a": 1}` |
| Comments | `{"a": 1 // note}` | `{"a": 1}` |
| Missing comma | `{"a": 1 "b": 2}` | `{"a": 1, "b": 2}` |
| Python literals | `{"ok": True, "x": None}` | `{"ok": true, "x": null}` |
| Leading zero | `{"n": 007}` | `{"n": 7}` |
| Raw line break in a string | `"line one` ↵ `line two"` | `"line one\nline two"` |

#### Why numbers stay exact here

JavaScript stores every number as a 64-bit float, so `JSON.parse` silently rounds integers above 9,007,199,254,740,991: `12345678901234567890` becomes `12345678901234567000`. That corrupts order IDs, tweet IDs and account numbers. This formatter keeps each number’s original text, so the output is exactly what you pasted — only the whitespace changes.

#### Pretty-printed vs minified JSON

- **Pretty-printed** (2 or 4 spaces, or tabs) is for people: logs, config files, code reviews and documentation.
- **Minified** removes all optional whitespace and is for machines: API payloads, local storage and anything sent over the network. For typical JSON it is 10–30% smaller than 2-space formatting, before gzip.
- **Sorted keys** make two JSON documents easy to compare in a diff, because the same keys always appear in the same order.

#### JSON syntax in 60 seconds

- Values are strings, numbers, `true`, `false`, `null`, objects `{}` or arrays `[]`.
- Strings and keys use **double quotes** only. Escape `"` as `\"` and a backslash as `\\`.
- Items are separated by commas, with no comma after the last one.
- Numbers have no leading zeros, no `+` sign, and no `NaN` or `Infinity`.
- Comments are not part of JSON. Use JSONC or JSON5 files if you need them, and strip comments before parsing.

### FAQ

**Why does my number look different in other tools?**
Most online formatters use JavaScript’s JSON.parse, which rounds integers larger than 2^53. This tool keeps numbers exactly as written, so large IDs stay correct.

**Can it handle large JSON files?**

**Does it support JSON5 or JSONC?**

**What happens with duplicate keys?**
The JSON standard leaves duplicates undefined; most parsers keep the last value. This tool does the same and shows a warning with the line of each duplicate, so you can fix the source.

**Can I download the result?**
Yes. Click **Download** to save the output as formatted.json or minified.json, or **Copy** to put it on your clipboard.

### At a glance

- Converts **XML to JSON** and **JSON to XML**, instantly as you type.
- Attributes become keys with a prefix (`@` by default), text beside attributes goes into `#text`, and repeated elements become arrays — all configurable.

- Runs in your browser: the data you paste or open is never uploaded.

### Features

- **Both directions**: XML → JSON and JSON → XML in one tool. Switching direction carries the result across, so you can convert back and forth.
- **Safe numbers**: Unlike many converters, it never turns “00482” into 482 or rounds a 20-digit ID. Only values that convert exactly become numbers.
- **Predictable arrays**: Turn on **Always use arrays** so code that reads the JSON works the same for one item or a hundred.
- **Exact error locations**: An unclosed tag or a missing comma is reported with its line and column, and one click jumps to it in the input.
- **Your naming**: Choose the attribute prefix (@, _, -, $), rename the text key, drop namespace prefixes or ignore attributes entirely.
- **Private**: Configs, API responses and feeds are converted on your device. Nothing is sent to a server.

### How to convert XML to JSON

1. **Add your XML** — Paste XML into the input, or click **Open file** to load an .xml, RSS or other XML file.
2. **Adjust the options** — Open **Options** to change the attribute prefix, keep every element as an array, or turn off number conversion.
3. **Check the result** — The JSON appears as you type. If the XML has an error, its line and column are shown.
4. **Copy or download** — Copy the JSON or download it as a file. Choose **JSON → XML** to convert in the other direction.

### Guide

#### How XML maps to JSON

| XML | JSON |
| --- | --- |
| `<name>Asha</name>` | `"name": "Asha"` |
| `<user id="7"/>` | `"user": { "@id": 7 }` |
| `<price currency="INR">799</price>` | `"price": { "@currency": "INR", "#text": 799 }` |
| `<tag>a</tag><tag>b</tag>` | `"tag": ["a", "b"]` |
| `<sku>00482</sku>` | `"sku": "00482"` (leading zero kept) |
| `<empty/>` | `"empty": ""` |
| `<![CDATA[<b>bold</b>]]>` | `"<b>bold</b>"` |

#### How JSON becomes XML

- Keys that start with the attribute prefix (`@id`) become attributes; the `#text` key becomes the element’s text.
- Arrays repeat the element: `"item": [1, 2]` becomes `<item>1</item><item>2</item>`.
- `null` and empty strings become empty elements like `<notes/>`.
- XML needs one root element, so data with several top-level keys, or a top-level array, is wrapped in `<root>`.
- Keys that aren’t valid XML names are made valid: `"first name"` becomes `<first_name>`, `"2nd"` becomes `<_2nd>`.
- Numbers are written exactly as they appear in the JSON, and `&`, `<` and `>` are escaped.

### FAQ

**Is it safe to convert confidential XML here?**
Yes. Conversion happens in your browser, so API responses, configs and feeds are never uploaded or stored.

**Why are some numbers kept in quotes?**
Values like `00482` or 20-digit IDs would change if turned into JSON numbers, so they stay as text. Turn off **Convert numbers & booleans** to keep every value as text.

**Why is a single element not an array?**
By default an element becomes an array only when it repeats. Turn on **Always use arrays** to make every element an array, so the structure never changes with the data.

**What happens to attributes?**
They become keys with a prefix — `@id` by default — placed before the element’s children. You can choose `_`, `-` or `$` instead, or ignore attributes.

**Are XML comments kept?**
No. JSON has no comments, so XML comments and the `<?xml ?>` declaration are dropped. CDATA content is kept as text.

**Can I convert JSON to XML?**
Yes. Choose **JSON → XML**. Keys starting with `@` become attributes and arrays become repeated elements, so XML converted to JSON here converts back to the same XML.

**Does it work with RSS, SOAP and sitemap files?**
Yes — any well-formed XML. Use **Remove namespace prefixes** for cleaner keys from SOAP and RSS media tags.

2. **Pick a record type** — Leave **All records** selected for a full overview, or choose one type such as **MX** or **TXT**.
3. **Look it up** — Click **Look up**. Records appear grouped by type, with their TTL and a short explanation.
4. **Compare or copy** — Switch the **DNS server** to compare answers, copy records, or open the **propagation checker** to see the answer worldwide.

### Guide

#### DNS record types explained

| Type | What it does | Example |
| --- | --- | --- |
| A | Points a name to an IPv4 address | 203.0.113.10 |
| AAAA | Points a name to an IPv6 address | 2001:db8::10 |
| CNAME | Makes a name an alias of another name | www → example.netlify.app |
| MX | Mail servers for the domain, with priority | 10 mail.example.com |
| NS | Name servers that hold the domain’s records | ada.ns.cloudflare.com |
| TXT | Text: SPF, DMARC, DKIM, verification codes | v=spf1 include:_spf.google.com ~all |
| SOA | Zone details: primary server, admin, serial, timers | ns1.example.com … |
| CAA | Which authorities may issue SSL certificates | 0 issue "letsencrypt.org" |
| PTR | Host name for an IP address (reverse DNS) | dns.google |

#### Checking your email setup

For email to arrive — and for your own mail not to land in spam — a domain needs **MX** records pointing to its mail provider, an **SPF** TXT record listing the servers allowed to send for it, and a **DMARC** record at `_dmarc.yourdomain` saying what to do with mail that fails the checks. Gmail and Yahoo require SPF and DMARC from bulk senders.

There must be **only one SPF record**: two SPF records make both invalid. Start DMARC with `p=none` to monitor, then move to `quarantine` or `reject` once all your sending services pass. DKIM keys live at `selector._domainkey.yourdomain`; look them up by typing that full name and choosing **TXT**.

### FAQ

**What is a DNS lookup?**
A DNS lookup asks the Domain Name System for the records of a name — for example the IP address of a website (A record) or the mail servers of a domain (MX). It’s what your browser does every time you visit a site.

**Why does the DNS server I choose give a different answer?**
Each DNS server caches answers for the record’s TTL. After a change, some servers still hold the old answer until their copy expires. Sites on a CDN may also give different answers by location. Use the DNS Propagation Checker to see many servers at once.

**What does TTL mean?**
Time to live: how long DNS servers may keep an answer before asking again. A TTL of 1 hour means a change can take up to an hour to reach everyone. Lower it a day before planned changes.

**How do I do a reverse DNS lookup?**
Enter an IP address, such as 8.8.8.8. The tool looks up its PTR record automatically and shows the host name, if the owner of the address has set one.

**Is this the same as nslookup or dig?**
It gives the same answers as `nslookup` or `dig` pointed at a public resolver, in your browser and with explanations. **Copy records** gives you dig-style output.

**What is sent, and to whom?**
Only the name you look up and the record type, sent from your browser over encrypted DNS-over-HTTPS to the DNS server you pick (Google Public DNS by default). JustTools doesn’t receive or store your lookups.

### How to check DNS propagation

1. **Enter your domain** — Type the domain or subdomain you changed, such as **www.example.com**.
2. **Choose the record type** — Pick **A** for a new server IP, **CNAME** for an alias, **MX** for email, **NS** for new name servers or **TXT** for verification codes.
3. **Add the new value** — Optionally type the value you set, so each server is marked as updated or not.
4. **Check** — Click **Check**. Results fill in within seconds; switch on auto-refresh to follow the change.

### Guide

#### How long does DNS propagation take?

There is no single “propagation” process: every DNS server keeps a cached copy of your old record until its **TTL** (time to live) runs out, then fetches the new one. So a change is visible everywhere after at most the old record’s TTL — often 5 minutes to 1 hour, sometimes up to a day.

**New name servers (NS)** take longer: the registry for your domain’s ending (.com, .in…) publishes them, and resolvers may keep the old delegation for up to 48 hours. To make planned changes fast, lower the record’s TTL to 5 minutes a day before the change, then raise it again afterwards.

#### Reading the results

| You see | What it means |
| --- | --- |
| Updated (green tick) | The server returns the value you expect. |
| Different value (red) | The server still has the old answer cached — wait for its TTL to run out. |
| No record | The name exists but has no record of this type on that server (possibly cached). |
| Domain not found | The server believes the name doesn’t exist — common just after registering or adding a subdomain. |
| Different answers by country | Normal for sites on a CDN or GeoDNS: visitors are sent to their nearest server. |
| No answer | That server couldn’t be reached from your network (it may be blocked by a firewall or ad blocker). |

### FAQ

**Why do I still see the old website after the checker shows 100%?**
Your computer, router or browser can cache DNS too. Try another browser or a private window, restart the router, or switch your device to a public DNS such as 1.1.1.1 or 8.8.8.8. On Windows, `ipconfig /flushdns` clears the system cache.

**Can I speed up DNS propagation?**
You can’t force other servers to drop their cache, but you can plan ahead: lower the TTL well before a change. Google and Cloudflare also offer web pages to purge their cached copy of a name.

**Are these servers really in different countries?**
The public DNS networks are global: each answers from its site nearest to you, with its own cache. The country rows ask Google Public DNS to answer as it would for users of each ISP network, using EDNS Client Subnet — accurate for CDN and GeoDNS answers, but served from Google’s cache near you.

**Why do different countries get different IP addresses?**
Sites on a CDN (Cloudflare, CloudFront, Akamai, Fastly) or with GeoDNS deliberately give visitors the address of a nearby server. That’s expected and not a propagation problem.

**Why does it say “Domain not found” for a domain I just registered?**
New domains can take from minutes to a few hours to appear, and servers that asked before it existed remember the “not found” answer for the zone’s negative-cache time (shown as TTL).

**What is sent, and to whom?**
Only the domain and record type, sent from your browser over encrypted DNS-over-HTTPS to the DNS services listed on the page. JustTools doesn’t receive or store your checks.

**Is my data uploaded anywhere?**

**Can I convert CSV back to JSON?**

### Guide

#### Which UUID version should I use?

| Version | Made from | Use it for |
| --- | --- | --- |
| v4 | 122 random bits | General-purpose unique IDs — the default choice |
| v7 | Unix time in ms + random bits | Database primary keys and anything you sort by creation time |
| v1 | Time + clock sequence + node | Older systems that expect time-based UUIDs |
| v5 | SHA-1 of a namespace and a name | The same ID every time for the same input |
| v3 | MD5 of a namespace and a name | Compatibility with systems that already use v3 |

#### Are UUIDs really unique?

A version 4 UUID has 122 random bits: about 5.3 × 10³⁶ possible values. You would need to generate a billion UUIDs every second for about 86 years before the chance of a single duplicate reached 50%. In practice, UUIDs from a good random source never collide.

UUIDs aren’t secrets, though: don’t use them as passwords or security tokens. And while v7 UUIDs are great database keys, they reveal the time they were created.

### FAQ

**What is the difference between a UUID and a GUID?**
None in practice. GUID (globally unique identifier) is Microsoft’s name for a UUID. Windows and .NET often show GUIDs in uppercase and in braces — switch on Uppercase and choose { } to match.

**Is UUID v7 better than v4?**
For database keys, usually yes: v7 UUIDs increase over time, so new rows go at the end of the index instead of random places, which keeps inserts fast. Use v4 when the creation time shouldn’t be visible.

**Are these UUIDs safe to use in production?**
Yes. They follow RFC 9562 and use your browser’s cryptographically secure random number generator — the same quality as crypto.randomUUID() or uuid libraries.

**How do I check whether a string is a valid UUID?**
Open Decode & validate and paste it. The tool accepts common formats — with or without hyphens, braces or urn:uuid: — and shows the version, variant and, for time-based versions, when it was created.

**Why does v5 give the same UUID every time?**
That’s the point of name-based UUIDs: the same namespace and name always produce the same UUID, so different systems can derive matching IDs without talking to each other.

**Can a UUID be decoded to get the time?**
For versions 1, 6 and 7, yes — the creation time is stored inside. Version 4 is purely random, and v3 and v5 are hashes, so they contain no time.

### FAQ

**What is URL encoding?**
URLs may only contain a limited set of characters. URL (percent) encoding replaces any other character — spaces, &, non-English letters, emoji — with % followed by the hexadecimal value of each of its UTF-8 bytes, such as %20 for a space.

**Should a space be %20 or +?**
Both mean a space, in different places. %20 works everywhere in a URL; + means a space only in query strings and form data. When decoding, keep “+ means space” on for query strings and form data.

**What’s the difference between encodeURI and encodeURIComponent?**
encodeURI encodes a complete URL but leaves characters that structure it — : / ? & = # — alone. encodeURIComponent encodes those too, which is right for a single value you put inside a URL, but would break a whole URL.

**Why does decoding fail with “malformed URI”?**
The text contains a % that isn’t followed by two hexadecimal digits (like “50%off”), or bytes that aren’t valid UTF-8. The tool shows the exact character; encode a literal % as %25.

**What is double encoding?**
Encoding text that’s already encoded, so %20 becomes %2520. The tool notices when a decoded result still contains escapes and offers to decode it again.

**Is my URL sent anywhere?**
No. Encoding, decoding and parsing all happen in your browser.

No. Encoding and decoding happen entirely in your browser, including for files.

#### Things that often go wrong

**Time zones:** cron uses the server’s time zone, GitHub Actions always uses UTC, and EventBridge rules run in UTC. Check the next runs in UTC if your job runs at the “wrong” hour.

**Both day fields in Unix cron:** `0 0 1 * 1` runs on the 1st **and** every Monday, not only on Mondays that are the 1st.

**Day numbers:** Monday is 1 in Unix and Spring but 2 in Quartz and AWS. Using names like MON avoids mistakes.

### FAQ

**How do I run a cron job every 5 minutes?**
Use `*/5 * * * *` in Unix cron. In Quartz it’s `0 */5 * * * ?`, in Spring `0 */5 * * * *` and in AWS `*/5 * * * ? *`.

**What does * * * * * mean?**
Every minute. The five fields are minute, hour, day of month, month and day of week; * means “every”.

**What is the difference between Unix cron and Quartz cron?**
Quartz adds a seconds field at the start (and an optional year), numbers days of the week 1–7 starting with Sunday, needs a “?” in either day-of-month or day-of-week, and supports L, W and #. The tool converts between them.

**How do I schedule a job on the last day of the month?**
Use L in day-of-month in Quartz, Spring or AWS, e.g. `0 0 0 L * ?`. Standard Unix cron has no last-day option; a common workaround is to run daily on days 28–31 and check the date in the script.

**Why does my GitHub Actions schedule run at a different time?**
GitHub Actions cron is always in UTC (and may start a few minutes late when busy). India is UTC+5:30, so 9:00 AM IST is `30 3 * * *`. Switch Next runs to UTC to check.

**Can cron run every 30 seconds?**
Not standard Unix cron — its smallest unit is a minute. Quartz and Spring have a seconds field: `*/30 * * * * ?` (Quartz) or `*/30 * * * * *` (Spring).

### Guide

#### Anatomy of a JWT

| Part | Contains | Example |
| --- | --- | --- |
| Header | The signing algorithm and token type, Base64URL-encoded JSON | {"alg":"RS256","typ":"JWT","kid":"key-1"} |
| Payload | The claims: who the token is about, for whom, and how long it lasts | {"sub":"42","aud":"api","exp":1767229200} |
| Signature | Proof that header and payload came from the key holder unchanged | Base64URL bytes of an HMAC, RSA, ECDSA or EdDSA signature |

#### Decoding is not verifying

Anyone can decode a JWT — the header and payload are only Base64URL-encoded, not encrypted. That is why tokens must never carry passwords or other secrets. **Verifying** checks the signature with the right key, which proves who created the token and that nobody changed a single character.

A server should verify the signature, then check **exp**, **nbf**, **iss** and **aud**, and accept only the algorithms it expects. Never trust the alg value or a key that arrives inside the token itself. Public keys for providers such as Auth0, Okta, Microsoft Entra ID, Cognito and Firebase are published at a JWKS URL, usually ending in /.well-known/jwks.json.

### FAQ

**Is it safe to paste a production token here?**

**Why does it say “Invalid signature”?**
The key doesn’t match the token, or the token was changed. Common causes: the wrong environment’s secret, a secret stored as Base64 but entered as text (switch the encoding), or a JWKS key with a different kid.

**Where do I find the public key to verify RS256 tokens?**
Identity providers publish them as a JWK set, usually at https://your-issuer/.well-known/jwks.json (OpenID Connect discovery lists the exact URL). Paste the whole JWKS — the key matching the token’s kid is used.

**Can it decrypt JWE tokens?**
No. Encrypted tokens (five parts) can only be read with the recipient’s private key; the debugger shows their header and says so.

**Why are exp and iat such large numbers?**
JWT times are seconds since 1 January 1970 UTC (Unix time). The debugger converts them to dates. Values in milliseconds are a common bug and are flagged.

### Guide

#### What an HMAC proves

An HMAC is a hash mixed with a secret key. Anyone with the same key and message gets the same value, and without the key it can’t be forged — so it proves a message came from someone who knows the secret **and** wasn’t changed on the way.

That’s why payment gateways and platforms sign webhooks with it: your server recomputes the HMAC of the raw body with the shared secret and accepts the request only if it matches the signature header. Compare with a **constant-time** function (`timingSafeEqual`, `hmac.compare_digest`, `hash_equals`) so the check itself doesn’t leak the signature.

| --- | --- | --- | --- |
| GitHub | X-Hub-Signature-256 | body | sha256=hex |

| Slack | X-Slack-Signature | v0:timestamp:body | v0=hex |
| Shopify | X-Shopify-Hmac-Sha256 | body | Base64 |
| Razorpay | X-Razorpay-Signature | body | hex |

| Cashfree | x-webhook-signature | timestamp + body | Base64 |
| Standard Webhooks | webhook-signature | id.timestamp.body | v1,Base64 |

### FAQ

**How do I generate HMAC-SHA256?**
Keep **HMAC-SHA256** selected, enter the secret key and the message. The HMAC appears instantly in hex and Base64 — copy the one your API expects.

**Why doesn’t my webhook signature match?**
Almost always because the body was changed before hashing — parsed and re-serialised JSON, a trailing newline, or different line breaks. Sign the raw bytes exactly as received. The second most common cause is the wrong secret, such as an API key instead of the webhook secret. This tool checks these for you.

**Is HMAC the same as hashing with a salt?**
No. HMAC uses the key in a special two-pass construction that stays secure even with hashes like MD5 or SHA-1. Simply hashing key + message is open to length-extension attacks. For passwords, use bcrypt or Argon2 instead — see the [Bcrypt Generator & Checker](https://justtools.online/security-tools/bcrypt-generator/).

**How long should an HMAC key be?**
At least as long as the hash output — 32 random bytes for HMAC-SHA256. Keys longer than the block size (64 bytes for SHA-256) are hashed first, so they add nothing.

**Hex or Base64 — which should I use?**
They are the same bytes written differently. Use whatever the other side expects: GitHub, Stripe and Razorpay use hex; Shopify, Cashfree and Standard Webhooks use Base64.

**Are my keys sent anywhere?**
No. Everything is computed in your browser, and keys, secrets and messages are not saved — only your algorithm and provider choice are remembered.
