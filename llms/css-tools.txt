### Guide

#### What glassmorphism is

Glassmorphism is a style of interface where cards, menus and panels look like frosted glass: you can see colours and shapes behind them, softly blurred, while text on top stays sharp. Apple uses it across macOS and iOS, Windows calls its version acrylic, and it became a web design trend in 2020.

In CSS the effect comes from one property, `backdrop-filter`, which blurs whatever is behind an element. It only shows when the element’s own background is partly transparent — a solid background hides the blur completely.

#### The CSS behind the effect

| Property | Typical value | What it does |
| --- | --- | --- |
| `background` | `rgba(255, 255, 255, 0.25)` | the tint: a see-through colour; lower opacity shows more of the background |
| `backdrop-filter` | `blur(16px) saturate(180%)` | blurs what is behind; saturation above 100% makes those colours richer |
| `-webkit-backdrop-filter` | the same | the same, for Safari before version 18 |
| `border` | `1px solid rgba(255, 255, 255, 0.45)` | a light edge that separates the glass from the background |
| `box-shadow` | `0 6px 21px rgba(0, 0, 0, 0.14)` | lifts the card; an inset line can add a bright top edge |
| `border-radius` | `24px` | rounded corners, typical of glass surfaces |

#### Keeping text readable on glass

Text on glass sits on a background that changes from place to place, so it can be readable in one corner and not in another. WCAG 2 asks for a contrast of at least **4.5:1** for normal text and **3:1** for large text. This tool measures the glass over the whole card and reports the weakest spot.

If text is hard to read, raise the tint opacity, blur more (which evens out the background), switch between dark and light text, or give the text its own slightly darker or lighter panel.

### FAQ

**Why does my backdrop-filter blur not show?**
Usually because the element’s background is solid — the blur is behind it, so make the background partly transparent. Also check that there is something behind the element to blur. If a parent element has its own filter, opacity below 1, a mask or a backdrop-filter, the specification says the blur only sees what is inside that parent (it calls this the backdrop root).

**Do I still need -webkit-backdrop-filter?**
Only for Safari 17 and older, which understood the prefixed name only. Safari 18 and every current Chrome, Edge and Firefox read `backdrop-filter`. Keeping both lines costs nothing, so the tool writes both.

**How do I make glassmorphism in Tailwind CSS?**
Use a semi-transparent background, a backdrop blur and a light border, for example `bg-white/25 backdrop-blur-lg backdrop-saturate-180 border border-white/45 rounded-3xl`. Open the **Tailwind** tab to get the classes for your exact settings.

**Is glassmorphism bad for performance?**
backdrop-filter makes the browser redraw what is behind the element whenever it changes, which costs more on large areas, big blur values and older phones. Use it on cards, menus and dialogs rather than whole pages, and avoid stacking many glass layers on top of each other.

**What is the difference between glassmorphism and neumorphism?**
Glassmorphism is see-through: a blurred view of what is behind. Neumorphism is solid: soft light and dark shadows make an element look pressed out of, or into, the same coloured surface. Try the [CSS Neumorphism Generator](https://justtools.online/css-tools/neumorphism-generator/) for that look.

**What does “Reduce transparency” do with my glass?**
Some people switch on Reduce transparency because see-through surfaces are tiring or hard to read. With **Add fallbacks** on, the CSS gives them a solid surface through the `prefers-reduced-transparency` media query, in a colour that keeps your text readable.

**Can it make Apple’s “Liquid Glass” look?**
Not the bending of light at the edges: that needs an SVG displacement filter inside backdrop-filter, which for now works only in Chromium browsers such as Chrome and Edge. This tool makes the frosted glass that works in every current browser, and the bright top edge and sheen give some of the same feel.

**Is my photo uploaded?**
No. The photo is read by your browser to show it behind the glass and to measure contrast, and it is never sent anywhere or saved. Your slider settings are kept in this browser’s local storage only.

### Guide

#### How neumorphism works

Neumorphism (new skeuomorphism, or soft UI) makes elements look moulded from the background itself. The element has the same colour as the surface behind it, and two shadows shape it: a dark one on the side away from the light and a light one on the side facing it.

In CSS that is a single `box-shadow` with two values, such as `16px 16px 32px #bfc3ca, -16px -16px 32px #ffffff`. The word `inset` in front of both turns the shape into a hollow; a gradient background makes it convex or concave.

#### The four shapes

| Shape | Background | Shadow | Looks like |
| --- | --- | --- | --- |
| Flat | the surface colour | outside | a raised, flat-topped tile |
| Convex | gradient, light side lighter | outside | a domed button |
| Concave | gradient, light side darker | outside | a raised dish |
| Pressed | the surface colour | inset | a hole or a pushed-in button |

#### Making neumorphism accessible

- WCAG 2.1 asks for **3:1** contrast for the visual boundary of buttons, inputs and other controls (success criterion 1.4.11). Soft shadows rarely reach it, so add a border to anything people must find and use — **Visible edge** does this with a colour that passes.
- Text needs **4.5:1** against the surface (3:1 for large text). Grey-on-grey text is the most common neumorphism mistake.
- Do not rely on the pressed look alone to show that a toggle is on; add a label, an icon or a colour change.
- Windows High Contrast mode removes box-shadows. The CSS adds a border inside `@media (forced-colors: active)` so every element still has an outline.
- Keep a visible focus ring for keyboard users; the tool’s button states include one.

### FAQ

**Why does neumorphism not work on a white background?**
The light shadow has to be lighter than the surface, and nothing is lighter than white — so the top edge disappears. Use a light grey such as `#e0e5ec` or `#f0f0f3` instead; the tool warns you when the surface is too light or too dark.

**How do I make a neumorphic button pressed when clicked?**
Give the button an inset version of its shadow in `:active`, for example `.neu:active { box-shadow: inset 9.6px 9.6px 19.2px #bfc3ca, inset -9.6px -9.6px 19.2px #ffffff; }`. With **Button states** on, the tool writes this for you, plus a focus ring and a smooth transition.

**How do I do neumorphism in Tailwind CSS?**
Use arbitrary values: a background the same as the page, such as `bg-[#e0e5ec]`, and a shadow like `shadow-[16px_16px_32px_#bfc3ca,-16px_-16px_32px_#ffffff]`. The **Tailwind** tab gives you the exact classes for your settings, including `active:` and `focus-visible:` states.

**Can neumorphism work in dark mode?**
Yes. Choose a dark surface such as `#2b2f36` and raise the intensity a little, because shadows show less on dark colours. Use light text and check its contrast in the panel under the preview.

**Is neumorphism bad for accessibility?**
It can be, because the shapes are drawn only with subtle shadows. It works when you add a visible border to controls, keep text contrast at 4.5:1 or more, and never use the pressed look as the only sign of state. The tool checks the first two for you.

**What is the difference between concave and convex?**
Both are raised from the surface. Convex has a gradient that is lighter on the side facing the light, so it bulges like a dome; concave has the opposite gradient, so it looks like a shallow dish.

**Are my settings saved?**
They are kept in this browser’s local storage so they are still there next time. Nothing is uploaded.

### Guide

#### What a bento grid is

A bento grid arranges content in tiles of different sizes inside one rectangle, like the compartments of a Japanese bento lunch box. A large tile carries the main message and smaller ones hold details, stats or images. Apple’s product pages made the style popular, and it now appears on portfolios, landing pages and dashboards.

CSS Grid is made for it: one container with `display: grid`, columns of equal width, and each tile told how many columns and rows to span.

#### How the generated CSS works

`grid-auto-rows: minmax(…, auto)` gives every row a minimum height but lets it grow when a tile has more content, so text is never cut off.

| Screen | Columns | How tiles are placed |
| --- | --- | --- |
| Phone (under 640 px) | your phone setting, usually 1 | one after another in reading order; tall tiles keep their height |
| Tablet (640–1023 px) | your tablet setting, usually 2 | spans shrunk to fit, in reading order |
| Desktop (1024 px and up) | as drawn | exactly where you drew them, with `grid-template-areas` or line numbers |

#### Bento layouts that work for everyone

- Keep the HTML in the order people should read it. This tool writes tiles left to right, top to bottom, exactly as you see them on desktop.
- `grid-auto-flow: dense` fills holes by moving later tiles up. That can make the order on screen differ from the order a keyboard or screen reader follows — fine for pictures, not for links and buttons.
- Put the most important content in the biggest tile; it is also the first tile on phones.
- Give tiles enough contrast with the page background, and let text wrap instead of fixing tile heights.

### FAQ

**How do I make a bento grid in CSS?**
Use a grid container, for example `display: grid; grid-template-columns: repeat(4, minmax(0, 1fr)); gap: 16px;`, then give big tiles a span such as `grid-column: span 2; grid-row: span 2;`. Draw your layout here and the tool writes all of this, plus the rules for tablets and phones.

**What is grid-template-areas?**
A CSS property that lets you draw the layout in text: each quoted string is a row and each word is a cell, so `"hero hero stats"` puts the hero tile across two columns. A dot marks an empty cell. Each tile then gets `grid-area: hero;`.

**How do I make a bento grid with Tailwind CSS?**
Use `grid` with responsive column counts such as `grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`, a row height like `auto-rows-[minmax(180px,auto)]`, and spans on the tiles such as `row-span-2 sm:col-span-2`. The **Tailwind** tab gives you the exact classes for your layout.

**How does the layout change on mobile?**
On phones the tiles stack in reading order in the number of columns you choose (one by default). On tablets, wide tiles shrink to fit the tablet columns. Open the **Phone** and **Tablet** views to see it before you copy the code.

**Why are there holes in my tablet layout?**
In reading order, a wide tile sometimes cannot fit next to the tile before it, so it starts a new row and leaves a gap. Change the tile sizes or the tablet columns, or switch on **Fill holes on smaller screens**, which lets later tiles move up into the gaps.

**Can I edit the grid with a keyboard?**
Yes. Press Tab to reach a tile, then use the arrow keys to move it, Shift with the arrow keys to resize it, and Delete to remove it. **Add tile** puts a new tile in the first free cell.

**Is my layout saved?**
Yes, in this browser’s local storage, so it is still there when you come back. Nothing is uploaded.

### Guide

#### What scroll-driven animations are

A normal CSS animation runs over time. A scroll-driven animation runs over a scroll distance instead: `animation-timeline: view()` ties it to the element’s journey through the screen, and `animation-timeline: scroll()` ties it to how far the whole page has scrolled. Scroll down and the animation moves forward; scroll back up and it moves back.

`animation-range` says which part of that journey the animation covers. `entry 0% cover 40%` starts as the element’s top edge appears at the bottom of the screen and finishes when it is 40% of the way through its time on screen.

#### The range names

| Range | Covers the time when the element… |
| --- | --- |
| `entry` | comes into view at the bottom of the screen |
| `exit` | leaves at the top of the screen |
| `cover` | is at least partly on screen, from first to last pixel |
| `contain` | is completely on screen (or fills it, if it is taller than the screen) |
| `entry-crossing` | crosses the bottom edge of the screen |
| `exit-crossing` | crosses the top edge of the screen |

### FAQ

**Do scroll animations need JavaScript?**
Not in Chrome, Edge and Safari 26 or later: `animation-timeline` does it in CSS. Firefox only has it in test builds, so the tool adds a short optional script that does the same job there. **Plays once in view** always uses a small script, because only Chrome 146 and later can start an animation on scroll with CSS alone (`animation-trigger`).

**Why must animation-timeline come after the animation shorthand?**
The `animation` shorthand resets every animation property it does not mention, including `animation-timeline`. Written before the shorthand, the timeline would be thrown away and the animation would run on the clock instead. The generated CSS always puts it after.

Yes. AOS is a JavaScript library that adds classes as elements come into view. This tool writes the same kind of effect as a few lines of CSS — plus about 20 lines of script where needed — with nothing to install.

**What happens for people who prefer reduced motion?**
All movement sits inside `@media (prefers-reduced-motion: no-preference)`, so people who have asked their device to reduce motion see the content straight away with no animation. The reading progress bar still works, because it shows information rather than decoration.

**Will hidden elements stay invisible if the script fails?**
No. Elements are only hidden when the line in the page head has confirmed that the script will run, and in scroll-linked mode the hidden state exists only inside the animation itself. If anything fails, the content simply appears.

**Can I animate several elements one after another?**
Yes. With **Plays once in view**, set a **Stagger**: elements that come into view together start one after another. With **Follows the scroll**, each element already animates at its own position.

### Guide

#### How box-shadow works

The CSS `box-shadow` property draws one or more shadows around an element’s box, following its rounded corners. Each shadow is written as up to four lengths and a colour, with the word `inset` to put it inside the element. Separate several shadows with commas; the first one is drawn on top.

| Part | Example | What it does |
| --- | --- | --- |
| x offset | `0` | moves the shadow right (negative: left) |
| y offset | `8px` | moves the shadow down (negative: up) |
| blur | `24px` | how soft the edge is; 0 is a hard edge, and it cannot be negative |
| spread | `-4px` | grows the shadow (or shrinks it, if negative) before the blur |
| colour | `rgba(15, 23, 42, 0.12)` | usually a dark, see-through colour; without one, the text colour is used |
| `inset` | `inset 0 2px 4px …` | draws the shadow inside the element, so it looks pressed in |

#### Why layered shadows look better

A real shadow is sharp and dark close to an object and gets wider and fainter further away. One `box-shadow` layer can only do one of those at a time, so it looks either harsh or muddy. Stacking a few layers, each with double the offset and blur of the last, gets much closer — the idea Josh W. Comeau and Tobias Ahlin popularised as smooth or layered shadows.

Tinting helps too. A shadow on a blue page is not grey; it is a darker, duller blue. With **Colour from the background** on, the tool works out that colour for you in the OKLCH colour space.

#### Tailwind CSS v4 shadow values

From Tailwind CSS v4.3’s default theme. In v4, the old `shadow-sm` is now `shadow-xs` and the old `shadow` is now `shadow-sm`, so check the names when you upgrade from v3.

| Class | box-shadow |
| --- | --- |
| `shadow-2xs` | `0 1px rgb(0 0 0 / 0.05)` |
| `shadow-xs` | `0 1px 2px 0 rgb(0 0 0 / 0.05)` |
| `shadow-sm` | `0 1px 3px 0 rgb(0 0 0 / 0.1), 0 1px 2px -1px rgb(0 0 0 / 0.1)` |
| `shadow-md` | `0 4px 6px -1px rgb(0 0 0 / 0.1), 0 2px 4px -2px rgb(0 0 0 / 0.1)` |
| `shadow-lg` | `0 10px 15px -3px rgb(0 0 0 / 0.1), 0 4px 6px -4px rgb(0 0 0 / 0.1)` |
| `shadow-xl` | `0 20px 25px -5px rgb(0 0 0 / 0.1), 0 8px 10px -6px rgb(0 0 0 / 0.1)` |
| `shadow-2xl` | `0 25px 50px -12px rgb(0 0 0 / 0.25)` |

#### box-shadow or drop-shadow()?

`box-shadow` always follows the element’s box. `filter: drop-shadow()` follows the visible shape instead — the outline of a transparent PNG, an SVG icon or text. It has no spread and no inset, and several drop-shadows are applied one after another, so each one also shadows the shadow before it. Use the **drop-shadow** tab for images and icons, and box-shadow for cards, buttons and panels.

### FAQ

**How do I add more than one box shadow?**
Separate the shadows with commas in one `box-shadow` declaration, for example `box-shadow: 0 1px 2px rgba(0, 0, 0, 0.1), 0 8px 24px rgba(0, 0, 0, 0.12);`. A second `box-shadow` line would replace the first instead of adding to it. The first shadow in the list is drawn on top.

**How do I put a shadow on only one side?**
Offset the shadow towards that side and use a negative spread to pull the other edges in. For a shadow only at the bottom, try `0 8px 6px -6px rgba(0, 0, 0, 0.3)`. For one inside edge, use inset, as in `inset 0 2px 0 rgba(0, 0, 0, 0.1)` for the top.

**What is the difference between blur and spread?**
Spread changes the size of the shadow — positive spread makes it bigger than the element, negative makes it smaller. Blur then softens its edge; a blur of 0 gives a hard edge. A shadow with 0 offsets, 0 blur and 1px spread draws a 1px line around the element, which is a common way to make a border that takes no space.

**Why does my shadow look grey and dirty?**
Usually because it is one large, dark layer of pure black. Use several lighter layers instead (Smooth mode does this), keep each layer’s opacity low, and tint the shadow towards the background colour rather than black.

**How do I make shadows in Tailwind CSS?**
Use the built-in utilities such as `shadow-sm`, `shadow-md` or `shadow-lg`, or an arbitrary value for anything else — spaces become underscores, as in `shadow-[0_8px_24px_rgba(0,0,0,0.12)]`. The **Tailwind** tab writes the right one for your shadow, and the class names are for Tailwind v4.

**Do box shadows work on dark backgrounds?**
They are much harder to see, because there is little light to take away. On dark pages, raise the opacity, make the element lighter than the background, or add a faint light ring such as `0 0 0 1px rgba(255, 255, 255, 0.06)`. Use the **Dark** preview to check.

**Are box shadows bad for performance?**
Static shadows are cheap. Animating `box-shadow` itself makes the browser repaint each frame, which can stutter on large elements or slow phones. For many animated cards, put the hover shadow on a pseudo-element and animate its opacity instead.

**Which browsers support box-shadow?**
All of them. Every browser in use today supports box-shadow without a prefix, including multiple and inset shadows; the `-webkit-box-shadow` prefix has not been needed for over ten years.
