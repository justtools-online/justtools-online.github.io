At a glance

How hex becomes text

Computers store text as bytes, and hexadecimal is a compact way to write a byte: two digits from 00 to FF (0 to 255). An encoding maps bytes to characters — in ASCII, 48 is “H”, 65 is “e” and 20 is a space, so 48 65 6C 6C 6F reads “Hello”.

ASCII covers only English letters, digits and symbols (bytes 00–7F). UTF-8 keeps ASCII as it is and uses 2–4 bytes for everything else: “₹” is E2 82 B9 and “न” is E0 A4 A8. That’s why one Hindi character can turn into six hex digits.

FAQ

Frequently asked questions

How do I convert hex to text?

Choose Hex → Text and paste the hex. Spaces, 0x prefixes and separators don’t matter — every pair of digits is read as one byte and decoded as UTF-8 text.

What is the difference between hex to ASCII and hex to UTF-8?

For bytes 00–7F they are identical. Bytes above 7F aren’t ASCII at all; UTF-8 reads them as parts of multi-byte characters (Hindi, ₹, emoji), while Latin-1 reads each as one Western European letter such as é.

Why do I see � in the result?

Those bytes aren’t valid text in the chosen encoding. Try Latin-1, or the data may not be text at all — the tool recognises common files like PNG and PDF so you can download them.

Why does it say a value has an odd number of digits?

A byte is exactly two hex digits. An unbroken string like 486 can’t be split into whole bytes, so a digit is probably missing or extra.

Can I convert binary or decimal too?

Yes — switch Bytes as to Binary, Decimal or Octal. There’s also a dedicated Binary to Text Converter.

Is my data uploaded?

No. Conversion happens entirely in your browser, including files you open.
